# 差分判分定位（Differential Scoring）

**适用场景**：总分高而未满（如 95.75 vs 100），本地逐项核对"都对"，但就是不知道哪块丢分。这是最棘手的卡点——不是"做错了"，而是"不知道判官在比什么口径"。

**核心原则**：**先定位，后修复。** 定位不到丢分分量前，任何 A/B 都是盲试（期望收益低、耗 quota、有 N16 burst 风险）。

## When to Use

- harbor 总分 ≥90% 但未满 100，且本地核对无错。
- 已做 1-2 次单字段 A/B 均无变化（说明猜测的轴不是扣分点）。
- 判词中性（"Strong submission"）但就是不到满分。
- 缺口是"干净的"小缺口（如 4.25% = 某分量 83%），指向单一分量而非系统性错误。

## Step 0 — 量化缺口，推断分量权重

1. 读总分与满分差：`gap = 100 - score`。
2. 推断分量权重：若题目是 N 等分（如 4×25%），`gap ≈ (1/ N) × deficit` 意味着**恰好一个分量掉到 (100%−deficit)**，其余满分。
   - 例：KMC `gap=4.25%`，4 分量 → 某分量 = `100% − 4.25%×4 = 83%`。这是"单分量掉分"的指纹。
3. 若 gap 不整除，考虑多分量共同小幅掉分（更隐蔽，需 Step 3 定向突变逐个测）。

## Step 1 — 零 quota 差分（先做，成本最低）

按成本从低到高，**每一步拿到信号就停**：

1. **判官明细 probe**（首选，见 `oracle-probe`）：读 worker/判分器侧的**分量级评分、运行日志、逐项校验结果**。很多判分器会把 per-component 分数写进日志或 scorecard 明细，只是没被读出来。
2. **判词逐词挖掘**：scoringDetails 原文，找指向具体分量的措辞：
   - "not genuinely-derived / leaning on paper" → 推导/引用分量
   - "incomplete / missing" → 完备性分量
   - "units / mismatch" → 量纲/单位分量
   - "trace" → trace 分量（注意 factor 是否已 1.0）
3. **100 分档 diff**：若能取到满分 attempt 的 outputs（未 redacted），与我方逐字段 diff——**口径差（CI 约定/窗口/舍入/保留名）往往就藏在 diff 里**。
4. **档位对称性**：全场分数分布，看满分档与我方档之间差的是哪个子项（结合判词）。

## Step 2 — 建立"分量假设清单"

把 Step 1 的信号转成**可检验的分量假设**（每个假设 = 一个分量 + 一个具体口径疑点）：

```
H1: 统计分量 83% —— Wilson CI 用区间 vs 判官要 Wilson score 的另一种边界
H2: 平衡分量 83% —— x_balance 的"负到正"方向约定 / bracket 端点
H3: 模型分量 83% —— label_exchange_check 的适用性（pass vs not_applicable）
H4: 核算分量 83% —— 某跨文件映射的口径
```

> 每个假设必须**可被单次提交区分**（能预测"若 H1 为真，改 X 会让分数动 Y"）。不能区分的假设先不花 quota。

## Step 3 — 定向突变（花 quota 换情报，性价比最高）

对**最可能的 1 个**分量假设做定向突变（而非盲试多个）：

1. **故意弄坏**该分量的一个口径（如把 CI 从 Wilson 换成正态、把窗口从 min(60) 改成全部），提交读 harbor。
2. **读响应**：
   - 分数**掉了** → 该分量确实在计分，且当前口径接近判官口径（弄坏才掉）。记下掉多少 → 反推该分量当前状态。
   - 分数**不动** → 该分量要么本来就满分、要么判官根本不比这个口径 → 排除该假设，转下一个分量。
   - 分数**反而升了** → 判官口径恰是我"弄坏"后的版本 → 直接锁定正确口径！
3. **每次突变后回滚**到基线，记录轴台账（attempt id + 增量）。

> **关键**：定向突变是"用 1 次 quota 买一个分量的是/否情报"，比"盲试 3 个字段"信息量大得多。KMC 局若先做这步，1 次提交就能确认"模型检查列不扣分"，省掉后续盲试。

> **破坏性提交级差分（通用手法，完整版见 `judge-field-audit` 阶段 B）**：缺口定位不确定/多假设竞争/判官口径分歧时，用破坏性差分裁决——故意弄坏**单个字段**提交读 harbor（变=受检且在拿分；不变=未受检/从未拿分）。纪律：每发提交前写一行"此发确立什么、每个结果导向什么"；**禁止 retry 循环**（失败=停下列线诊断）；差分必须覆盖**全部字段类型**（数值+字符串枚举——09 弄坏数值不动 ≠ 不检查，真丢分项是枚举串）；判官/红队分解一律视为待验证假设，提交级差分优先（09 29180 证伪判官 H1）。

## Step 4 — 定点清除（定位后）

1. 锁定丢分分量 + 具体口径后，做**单字段 A/B**：只改该字段到"判官口径"，读 harbor。
2. 预期：该分量从 83% → 100%，总分 +4.25%（若单分量指纹成立）。
3. 验证：重复 1 次确认确定性（同内容同分）。

## 诊断预算规则

- A/B 预算 **≥50% 用于 Step 1-3（定位）**，剩余用于 Step 4（修复）。
- 定位阶段每次突变只针对**一个**分量假设，突变后回滚。
- **禁止**在未定位前做"整包重写"（那是等价壳内穷举，违反禁卡死条例）。

## 回报格式（差分诊断卡）

```
题: <slug>
缺口: score=X, gap=Y% → 推断分量权重: <哪分量掉到 Z%>
分量假设: H1/H2/... （各附口径疑点）
零 quota 差分: <probe/判词/100分diff 的信号>
定向突变: <分量, 突变, attempt_id, harbor 增量, 结论(锁定/排除)>
已锁定: <分量 + 口径>
下一步: <单字段 A/B 计划 + 预期增量>
```

## 与相关技能的关系

- `platform-scorecard-analyze` Step 5 = 本技能的触发入口（分量级分解四法）。
- `oracle-probe` = 本技能 Step 1.1 的端点清单（判官只读诊断）。
- `unstuck-switch-angle` = 当差分诊断也定位不到、且本地饱和时的换角度兜底。
- `red-team-review` = Step 2 生成分量假设时的对抗性补充（找单位/模型/数值伪影/比对方法错误）。
