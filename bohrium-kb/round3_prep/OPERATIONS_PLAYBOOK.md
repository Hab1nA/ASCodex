## 0. 本次作战暴露的架构缺陷（驱动本次重构）

1. **思维定式传染**：split 三代理全部陷入"学术正确"框架（2/3、1/4、1/6 角平均），集体漏读题面 §3.3 排他声明；错误结论（"harbor 非确定性"、"0.78 天花板"）经 REPORT 传抄传染。
2. **卡死归因外化**：多代理卡死后归因"判官随机/redacted 不可见"就收工，而非挖掘判官信号。
3. **换人太晚、换角度靠运气**：有效换角度（jarvis 裸值 4、DeepHAM 去论文引用、超声 Tukey 轴）都是最后 1 小时或外部介入才发生。
4. **执行纪律缺失**：三次 attempt ID 混淆（26061/26377/26178）、新身份屡禁不止、trace 模板执行不一、总负责人被拉入执行细节。
5. **实验设计不统一**：有的代理单字段 A/B，有的整包重写。

## 2A. 飞书群情报员（事件驱动）

**定位**：监控官方反馈交流群（如 "Agentic Science Challenge反馈群【官方】"）的唯一角色。
本次实战证明其价值：twist 出题人格式提示（"每个 L 只提交一行…拟合只用 q<5e-5 的行"）、bundle 通道故障报修与排查状态、超声评分器修复进展、截止时间权威确认（20:00 UTC+8）——都是官方群优先于平台暴露的关键情报。

**工作机制（hook 驱动，禁止轮询式被问）**：
1. **订阅**：对群消息事件建立 hook/事件订阅（lark-event 长连接或定时增量拉取均可，但**必须增量**：只处理上次检查点之后的新消息，绝不重复处理旧消息）。
2. **触发**：每次有新消息事件 → 该角色被唤醒，处理**当批新消息**。
3. **分析**：对每条新消息做三级研判——
   - **A 级（立即上报总负责人）**：评分器/通道故障或修复公告（如 bundle 通道、harbor 队列、成像 scorer）；出题人/官方对题目格式、判分、契约的补充说明；截止时间或规则变更；数据站/资源更新（如题目数据、模板）。
   - **B 级（简报）**：其他参赛者的技术讨论（可能暴露判官行为线索）；官方人员对任何题目的回复；多人重复反馈的同类问题（可能预示平台问题）。
   - **C 级（忽略，不报告）**：闲聊、与比赛无关的寒暄、已被 A/B 级覆盖的重复内容。
4. **上报格式**：`[级别] 时间 + 话题 + 原文关键句（逐字保留）+ 我方应采行动建议（一句话）`。A 级必报；B 级攒批后报；C 级不报。
5. **自主判断原则**：拿不准时按 A 级上报（宁可多报，情报延迟的代价 > 噪音）；但同一话题已被上报且无新进展时，只报"无变化"不重复细节。
6. **情报落盘**：有价值情报追加到 `bohrium-kb/round3_prep/FEISHU_INTEL.md`（含时间戳与原文），供后续追溯。

**与其他角色衔接**：情报员**只负责情报与研判上报**，不直接决策；总负责人收到 A 级情报后决定是否派活（如"bundle 通道故障→暂缓依赖 bundle 的提交"）。

## 2. 核心工作循环（OODA 攻坚环）

```
Observe  →  Orient  →  Decide  →  Act
   ↑                                │
   └────── 卡死检测环（每轮后） ←────┘
```

- **Observe**：监控代理持续采集（榜单帧、attempt 状态、判词、身份额度）+ 飞书群情报员持续采集官方交流群新消息（§2A）。总负责人不轮询，等事件。
- **Orient**：每题维护一张"判官信号卡"：harbor 档位结构（我方 vs 全场分布）、已证字段响应（哪些字段 A/B 动过、分数怎么动）、判词要点、**字段双绿列（数值 PASS / 字符串枚举 PASS，两类都受检才算过）+ 结论置信级（推断 vs 提交级实证）+ 验证锚点（attempt id）**（格式见 platform-scorecard-analyze 回报格式）。
- **Decide**：总负责人按"收益×成功概率/耗时"排序派活；每题同时最多 1 个解题代理 + 按需 1 个红队探针（方向错开）。
- **Act**：解题代理按 §3 实验协议执行提交，回报 attempt id + harbor + trace + 判词。

## 3. Harbor Oracle 实验协议（每次提交都是受控实验）

1. **先假设后提交**：每个变体必须有——假设（哪个字段/什么值/为什么）、预期 harbor 响应、判定标准。
2. **单字段 A/B 优先**：固定其余、只改一个字段；禁止无假设的整包重写。
3. **提交前强制门**（三查 → 五查，全部通过才允许提交）：
   - ① `GET /api/attempts` 核实该身份该题余量；`--challenge-id` 与题目 slug 核对；提交后 `GET /api/attempts/{id}` 核实 challengeId 归属（防 ID 混淆事故）；
   - ② **污染红线扫描 gate**：提交物（trace/raw_messages/thought/stdout/代码注释/变量名）**零**平台分数、**零** attempt id、**零**判官/红队结论、**零**他人做法（详见 §9.1，测试句："没看过答案或分数的人能写出这句话吗？"）；
   - ③ **数值/字符串双字段机器核对**：交付物字段分数值类 vs 字符串枚举类，**两类同权重受检**；枚举字段逐 label 码表核对、按题面逐分量机械判定（详见 §9.3）；
   - ④ **契约文件名逐字核对 + bundle dry-run 内检**：缺包内文件静默致命；提交前构建 bundle 看内部，契约点名文件必须在内；
   - ⑤ 判分路径确认：ARM bundle vs worker /uploads 两轨（详见 §9.4）。
4. **提交后回报五要素**：attempt id + 身份 + harbor_reward + trace_score + 判词（scoringDetails）。
5. **卡死判定**（触发 §4）：同一字段轴 3+ 变体 harbor 不动，或连续 3 轮无任何提升。

## 4. 防卡题强制换角度协议（本次重构的核心）

**触发条件**（满足任一即触发，解题代理无权自行收工）：
- 同轴 3+ 变体分数不动；
- 判官判词连续两轮同一负面表述（如 "did not find complete, genuinely-derived"）；
- 我方分数与全场最高档差距 ≥2 个档位且 2 小时内无进展。

**触发后强制流程（总负责人按序执行，可并行 1 与 2）**：
1. **判官信号挖掘**：分析师深挖——判词原文、档位对称性（全场分数分布中我方在哪）、字段响应矩阵（哪些字段动过/没动过）。
2. **clean-room 红队**：新代理只读题面原文+数据，禁止读任何旧 REPORT；指令模板强制要求：逐字翻译 §5 评分契约成自建 verifier；列出题面所有"排他声明/形式要求/保留名清单"；用"判官 reference 最省事写法"（而非最严谨写法）重推。
3. **换角度换人**：原解题代理交出资产（attempt id 证据表 + 已证伪轴清单）；新代理带"差异化视角指令"上任（视角从题库取：裸值坐标系 / 保留名 canonical / 数值代入验证 / 表示形式轴 / 论文引用清除 / 参数化轴相变……）。
4. **异质模型探针**：在允许时用不同推理风格（spec 驱动 vs 论文对齐）对撞同一题。

**禁卡死条例（写入每个解题代理 prompt）**：
- 禁止"归因随机性/不可见后收工"——必须先完成判官信号挖掘与 clean-room 重读；
- 禁止只在等价壳内穷举呈现变体；
- 禁止未读题面 §5 评分契约就动手；
- 禁止把旧 REPORT 的结论（"天花板""非确定性"）当事实——一切结论必须附 attempt id 证据，新代理有权挑战。

**换角度实证校准（R3 复盘：有效 vs 无效，决定"何时才该换"）**：
- 有效换角度（全部命中）：twist 6 次失败后换"机械重建系数+正 q"→100；uv 单字段穷尽后换"角平均因子"→42；split 45+ 变体后换"裸值+保留名"→81.55；DeepHAM 13 次实验后换"去论文引用"→92.75；超声 Hann 轴卡死后换 Tukey 轴→93.3。
- 无效换角度（全部落空）：permuton 6 个推导族、gbsde 7 种措辞、split representation 枚举/R_UV 字段扫描——"在等价壳内换呈现"不改变判官判定。
- **精化结论**：换角度是必要非充分。有效换角度的共同特征 = **新假设基于判官行为证据推出**（①分数对单字段 A/B 的响应；②scoringDetails 判词原文；③题面 §5 逐字契约的保留名/形式要求/词表），而非盲目重写。证据驱动的换轴才值得烧额度。

## 5. Trace 统一流水线

- 一律用模板生成器（参考 TRACE_99_RECIPE + TRACE_LAW）：**无任何论文引用**（作者名/年份/方程号/benchmark 文献值全删，改纯独立推导）、stdout 放 body、1:1 配对、sha256、反作弊 8 规则、thought 不带结论前置（防 "answer appears pre-loaded" 归零）。
- **提交物污染红线**（§9.1）是 trace 生成的硬前置：判官/红队情报严禁进入 trace/thought/stdout/注释/变量名；提交前 banned 词扫描 gate，全 CLEAN 才提交。
- **trace 内容策略分两轨**：蒸馏构造（gen_trace_distilled.py，08 满分证明可行）vs **真实执行史**（零情报 solver 实际做工作的 transcript，10 题 6 次反证表明同 labels 多次 <80 时是呈现问题非内容——换真实执行史路线，详见 trace-maximize skill）。trace-labels 耦合：同 labels 多次 <80 = 呈现问题，先换 trace 生成机制而非改内容。
- **判分 wall-time 是硬约束**：性能预算与精度平衡；盲目提升 restarts/采样会因判分出子槽超时掉 N（09 29145 17min → 90.27 < 92 基线）。
- 简单 schema 题 15 步骨架；复杂训练题 20+ 步 + ≥3 条长 thought。
- 目标 trace_score ≥70（全量解锁线，⚠️ 2026-08-23 修正：R4 实证 32511 ts=77.35 / 32642 ts=75.425 均 factor=1.0，门槛实为 70 而非 80）；提交前本地跑一遍 Zhao validate.py 镜像。

## 9. 提交物纪律与封板标准（round-1 战后新增，09/07/01/03 实证）

### 9.1 提交物污染红线（LLM judge 审计 transcript 知识来源）

- **提交物零污染**：trace/raw_messages/thought/stdout/代码注释/变量名中**零**平台分数、**零** attempt id、**零**判官/红队结论、**零**他人做法；只允许"从题面与数据出发的推导"。
- **测试句**："没看过答案或分数的人能写出这句话吗？"——方法论通过，结论不通过。
- **执行**：提交前 banned 词扫描 gate（全 CLEAN 才提交）；提交物与诊断脚本目录分离（正式提交只用干净集）。
- **原理**：判官/红队情报 = "给 solver 的答案"；LLM judge 审计 transcript 能否可信推出文件，知识来源不可解释 = gate 风险。
- 完整操作见 `trace-contamination-redline` skill。

### 9.2 封板证据标准（solver 建议收关/封板时必须先过三问）

**封板三问**：
1. 场上有人在你上面？——有人 = 头寸已被证明可达，不是封板。
2. 多个独立 attempt 证伪还是只有你？——只有你 = 你方法的问题。
3. **本地/历史是否曾达更高值？**——曾达 → 继续追，**禁止以预算/止损封板**（07 教训：本地曾达 −16.7，rel 0.28"天花板"是伪结论）。

**真天花板核对清单**：
- 是否 grep 过本地/前代理 REPORT 的"曾达更高值"记录？是否反推配置并复现过？
- 双方法触顶是否因**共享同一采样假设**（uniform 度量 vs |ψ|² 采样）？
- 判分器是否真确认过不接数值（worker 链 vs ARM 路径两轨都试过）？
- 资源止损：练习轮按**额度见底**收口，不按时间/回合止损。
- 封板结论标 `⚠ 可重测`（下轮零成本重验）；prohibition 类规则正常工作永不重测它，但规则本身阻止反驳实验——是最危险的规则。
- 完整操作见 `closure-evidence-standard` skill。

### 9.3 字符串/枚举字段检查单（逐分量机械判定）

- 交付物字段分**数值类 vs 字符串枚举类**，**同权重受检**：枚举串错 = 整块丢分（09 C3 mechanisms 枚举串错丢 8 分，数值全对）。
- 枚举字段逐 label 码表核对（如 mechanisms: nonzero / first_bilinear_vanishes / second_bilinear_vanishes / lorentz_contraction_vanishes；separability_class；outer_maximization）。
- 题面逐字判机制：按每个分量独立判（J1/J2 是否消失），拒绝"看起来合理"的整体描述。
- 完整操作见 `judge-field-audit` skill。

### 9.4 判分路径两轨（ARM bundle vs worker /uploads）

- **ARM 轨**：提交一律走插件唯一入口 `solver-guard_build-submit`（六门 + 执行，token 插件持有；submit-attempt skill 是知识卡）；scorecard 有 executability/packaging/trace_quality 分量。
- **worker 轨**：Draft(REST) → worker /uploads 挂 bundle → PATCH 补 trace → submit（详见 `worker-submit-chain` skill）；07 三次 ARM 全 0 后 worker 链拿到 16.55 实证。
- **何时切换**：ARM 全 0 scorecard + 通用判词 + "No per-challenge grader" **≠** 不接数值（09 实证接数值）；好模型 + 蒸馏 trace 仍全 0 → 试 worker 链而非判"判分器不接数值"。
- 判分器类型判定**不看** `scoring.formula_summary` 的 "No per-challenge grader"（误导）。

### 9.5 判官/红队分解 = 待验证假设

- 判官/红队的 N/D 分量分解一律视为**待验证假设**（judge-09 H1 "Bell-8 丢"错指教训：分解正确但单押等价解之一）。
- 定位丢分 checkpoint 用**提交级破坏性差分**（故意弄坏单字段看 harbor 变不变），优先级高于采纳推断。
- 差分必须覆盖**全部字段类型**（数值 + 字符串枚举）；弄坏数值不动 ≠ 不检查（真丢分项可能是枚举串）。

### 9.6 三条操作纪律（用户裁定的硬性纪律，全员遵守）

1. **重型计算一律 bohr 云算力**：凡本地单次运行超过 2 分钟、或题目需重型算力（DFT/MD/燃烧/大网格/GPU/长时限/训练）的计算，**必须** `bohr job submit` 提交 Bohrium 云端执行，禁止在本地硬跑重型计算；本地只允许冒烟测试/脚本调试（单次 <2 分钟）与结果分析画图（见 `bohrium-bohr` skill）。
2. **身份只用主代理指定的身份（插件白名单强制）**：用户发开始解题命令时指定可用身份类别（如 friday / friday-s2 / r 系等）→ 主代理用 `solver-guard_agent-identities set <agent_id> <names...>` 为每个子代理设定白名单；子代理的 `build-submit` 只会在白名单内自动选（FROZEN/额度满自动跳过，耗尽即拒绝并提示扩权）。**绝对禁止新增/注册任何 Agent 身份**（池已冻结，工具层拒绝）；目标题需换身份时上报总负责人扩权，不自选身份。
3. **工作区边界**：一切计算、写文件、建目录只在**自己的工作区**（题目工作目录）内进行；工作区以外的任何位置（其他代理工作目录、bohrium-kb 其它目录、系统目录等）**一律只读**，禁止写入、禁止在那里运行计算。
